## 执行摘要

本报告基于 **1337 篇** arXiv 候选论文的系统检索，深度精读 **56 篇**核心论文（含 2026 年 10 月最新技术报告），并对 **80 篇**相关工作进行速览。报告面向推理引擎与系统工程师，重点覆盖 MoE 的数学原理、架构演进、训练稳定性、推理系统与硬件协同。

### 十条核心结论

1. **MoE 的本质是"参数容量与每 token 计算量解耦"，它省算力但不省显存。** 671B 参数的 V3 每 token 只激活 37B，但全部 671B 权重必须驻留 HBM——这是所有推理工程难题的起点。

2. **稀疏度持续提升，激活参数保持稳定。** 从 GShard 的 2048 专家/top-2（约 4×），到 V3 的 256 专家/top-8（18×），再到 K3 的 896 专家/top-16（27×）、V4-Pro 的 384 专家/top-6（33×）。激活参数从 97B（GLaM）降到 37B（V3）、13B（V4-Flash）、6B（Qwen3.8-Next），但旗舰模型的激活参数仍维持在 30B 以上（多在 30–50B，K3 的 104B 是能力优先的例外）。

3. **架构演进是一部"瓶颈迁移史"。** 八个里程碑依次解决：输入空间划分（1991）→ 容量与 FLOPs 解耦（2017-2021）→ 集群训练通信（2020-2022）→ 开源产品化（2023）→ 知识切分（2024）→ 超稀疏扩容（2024-2025）→ 动态计算（2025）→ 语义与物理解耦（2026）。每一步都把瓶颈推到下一个位置。

4. **负载均衡经历了四代：aux loss → aux+z-loss → aux-loss-free → 推理侧 EPLB。** DeepSeek-V3 的 aux-loss-free（偏置项不进梯度）是 2024-2025 年最重要的训练技巧；推理侧的 EPLB（冗余专家 + 动态重排）是生产部署的必需。

5. **训练稳定性的三件套：aux-loss-free、FP8 细粒度量化、MuonClip。** V3 用 FP8 + aux-loss-free 做到 14.8T token 零不可恢复 spike；K2 用 MuonClip 做到 15.5T token 零 spike；Muon 正在取代 AdamW 成为大 MoE 的默认优化器。

6. **MoE decode 的瓶颈是 HBM 带宽，不是算力。** 算术强度 $AI = 2/b$（BF16 为 1 FLOP/byte），比 H100 的拐点（295 FLOP/byte）低近 300 倍。batch=1 时 GPU 算力利用率可能只有 1-2%；要进入 compute-bound，每专家 batch 需达到约 256。

7. **分离式部署（attention/FFN 分离）是 2025-2026 年推理系统的主线。** MegaScale-Infer、JANUS、Step-3 AFD、FinDEP 都把 attention 和 MoE FFN 放到不同的 GPU 池，各自独立扩缩容。JANUS 报告 4.7× 单卡吞吐提升。

8. **all-to-all 通信量 = $2Tkdb$，是 EP 的核心成本。** V3 单层约 939 MB、61 层约 57 GB。DeepEP（LL/HT 双模式 + hook 重叠）、NCCL EP（官方标准化 API）、UBEP（超节点优化）是当前三条主要路线。

9. **量化是 MoE 的"显存救命稻草"，且 MoE 比 dense 更鲁棒。** MoQE 证明专家权重可降到 2-bit；QMoE 把 1.6T 模型压到 160 GB（0.8 bit/param）；V4.1-Flash 用 CSA2 跨层复用 + FP4 KV cache，把每 token 的**全局** KV 占用压到 890 字节（约为 V4-Flash 的 1/4）。

10. **2026 年的旗舰格局：V4-Pro（1.6T/49B）、K3（2.8T/104B）、GLM-5（744B/40B）、Qwen3.8-Flash-Next（125B/6B）。** 共同趋势是"更大总参数 + 更小激活 + 更长上下文 + 混合注意力 + MoE 与注意力解耦"。

## 1. 为什么 MoE 成为 2024-2026 的主流

### 1.1 稠密模型的"三堵墙"

2020-2023 年，稠密模型的 scaling 遇到三堵墙：

1. **算力墙**：每 token 计算量随参数线性增长，推理成本无法承受；
2. **显存墙**：参数增长快于 HBM 容量增长；
3. **数据墙**：高质量 token 有限，大模型容易"训不足"。

MoE 解的是第一堵墙（算力），缓解第二堵墙（用稀疏激活降低"有效计算"对显存带宽的压力），但不解第三堵墙（反而需要更多数据）。

### 1.2 成本结构的量化对比

以"同等能力"为基准，比较 dense 与 MoE：

| 维度 | Dense（假设 400B） | MoE（V3 671B/37B） | 差异 |
|---|---|---|---|
| 训练 FLOPs | 6 × 400B × 15T | 6 × 37B × 14.8T | MoE ≈ 1/10 |
| 推理每 token FLOPs | 2 × 400B | 2 × 37B | MoE ≈ 1/10 |
| 推理显存 | 800 GB（BF16） | 1.3 TB（BF16） | MoE ≈ 1.6× |
| 推理通信 | 无 | all-to-all 939 MB/层（61 层合计 57 GB） | MoE 新增 |
| 工程复杂度 | 低 | 高（EP/均衡/通信） | MoE 显著更高 |

**结论**：MoE 用"显存 + 工程复杂度"换"算力"。在算力贵、显存便宜、团队有系统能力的场景，MoE 划算；反之则不划算。

### 1.3 2026 年的市场格局

- **开源旗舰**：DeepSeek-V4、Kimi K3、GLM-5、Qwen3.8、MiniMax-M2 全部是 MoE；
- **闭源旗舰**：GPT-6、Gemini 4、Claude 4.6 的具体架构未公开，但业界普遍推测为 MoE 或混合架构；
- **端侧**：仍以 dense 小模型为主，MoE 在"端侧大模型"（如 Qwen3-30B-A3B）中有应用。

**MoE 已经不是"一种选择"，而是"大模型的主流架构"**。2026 年新发布的开源 100B+ 模型，几乎全部是 MoE。
